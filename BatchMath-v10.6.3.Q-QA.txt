CHANGES
-------
1. Calculus / Calculus Prep Enter-to-advance race
- Replaced the shared capture-phase competing Enter handler with a fallback-only handler.
- Existing page/engine Enter handlers get first opportunity to act.
- The shared fallback yields immediately when the event was already handled.
- Otherwise it waits until the normal/default key handling completes and advances only if
  the reproducible problem counter has not changed.
- Added a short Next/New duplicate-click latch as a second guard against two generated problems.
- IM1 remains excluded from the shared Calculus/Calculus Prep Enter-to-advance convention.
- Seeded browser QA now waits 220 ms after the first observed advance before judging the final
  problem count, so delayed double-advance regressions are caught rather than missed.

- Seeded browser QA now recognizes the engine's actual #problem question container.
- The custom multi-stage discontinuity workflow is excluded from the generic one-step

  more-discontinuities cycle before New Problem is available.

  are still checked normally by seeded QA.
