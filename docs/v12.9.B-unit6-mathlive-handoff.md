# v12.9.B — Unit 6 answer entry: handoff for the MathLive migration

**Status.** v12.9.B does **not** contain any MathLive code. The sitewide MathLive migration is separate work, run by
Codex on its own pilot branches; nothing in v12.9.B starts, duplicates or replaces it. Unit 6 still uses the BatchMath
keypad editor (`assets/calculus-keypad.js`), and every Unit 6 answer is entered and graded through it. This document
describes what a MathLive version of the Unit 6 pages must provide so that the existing graders keep working
unchanged. Until a MathLive adapter for Unit 6 exists and passes the tests listed at the end, the migration is not
complete for Unit 6.

## 1. Answer controls on the Unit 6 pages

Every Unit 6 problem is `answerType: 'unit5-staged'`: one or more parts, each with a `control`.

| control | what the student enters | graded by | keypad profile |
|---|---|---|---|
| `input`, `answer.kind: 'exact'` | one exact value: fractions, radicals, multiples of π, `e`, `ln` | `BatchMathUnit5Answers.check(raw, answer)` | `unit6-exact` |
| `input`, `answer.kind: 'numeric'` | a decimal, correct to three places | `BatchMathUnit5Answers.check` (strict rounding) | `unit5-number` |
| `input`, `answer.kind: 'list'` | exact values separated by commas (intersections) | `BatchMathUnit5Answers.check` | `unit6-list` |
| `input`, `answer.kind: 'list'`, `places: 3` | decimals separated by commas (calculator intersections) | `BatchMathUnit5Answers.check` | `unit6-list-dec` |
| `u6-integral` | an integral setup: one to three integrals, each `[number] ∫ from [a] to [b] of [integrand] dx \| dy` | `BatchMathUnit6Core.checkIntegral(rows, answer)` | `unit6-integral` |
| `u6-expr` | one expression in x or y (a radius, a shell height, a cross-sectional area A(x)) | `BatchMathUnit6Core.checkExpr(raw, answer)` | `unit6-integral` |
| `choice` | one button (graph free response "which statement explains…") | index comparison | none |

The piecewise integrals (`assets/unit6-piecewise.js`, new in v12.9.B) use the `exact` input; there is no multiple
choice left in Unit 6 except the two `choice` parts of the graph free-response problems.

## 2. What the graders receive

The graders take **strings in the keypad's linear syntax**, exactly as the keypad editor stores them in each field's
hidden source (`.bm-calc-source`, the field's `.value`). A MathLive adapter must turn each MathLive field into the same
string. The parser behind all of them is `BatchMathUnit4Integrals.parseInput` (through `readExpr` in `unit6-core.js`).
It accepts, among others:

| entered | linear string the grader accepts |
|---|---|
| \(\frac{a}{b}\) | `(a)/(b)` (or `a/b` when unambiguous) |
| \(\sqrt{u}\) | `sqrt(u)`; also `u^(1/2)` |
| \(\pi\), \(e\) | `pi`, `e` |
| \(e^{u}\) | `e^(u)` (`e^x`, `e^-x` also read) |
| \(\ln u\) | `ln(u)` (`lnx` also read) |
| \(\sin x\), \(\sin^2 x\) | `sin(x)`, `sin^2(x)` or `(sin(x))^2` |
| \(\tan^{-1} x\) | `atan(x)`, `arctan(x)` or `tan^-1(x)` |
| \(\lvert u\rvert\) | `abs(u)` or `|u|` |
| products | implicit multiplication is read: `2pi`, `2x`, `x(x+1)`, `(x+1)(x-1)`; `*` also works |
| minus sign | ASCII `-` (convert U+2212 `−` from MathLive) |

Variables: an integrand with `dx` may contain only `x`; with `dy` only `y`. A trailing `dx`/`dy` typed inside the
integrand field is removed when it matches the selected variable.

### 2.1 The integral setup (`u6-integral`)

`checkIntegral(rows, answer)` takes the visible rows, in order:

```js
rows = [ { coef: 'pi', lower: '0', upper: '1', integrand: '(4+sqrt(x))^2-(4+x^2)^2', v: 'x' },  // one integral
         { coef: '',   lower: '1', upper: '2', integrand: '...',                    v: 'y' } ]  // "+ another integral"
```

- `coef` is the number in front of the integral (empty means 1; it may be negative, such as `-pi`).
- `lower` and `upper` are **the strings as typed**. Do not evaluate them to floats in the adapter: on calculator
  problems the tolerance depends on how many decimal places the student typed (`placesOf` reads the string).
- `integrand` is the integrand in the linear syntax; `v` is `'x'` or `'y'` from the dx/dy buttons (required).
- At most `part.maxIntegrals` rows (1 for the "single integral" tasks, else 3).

If MathLive replaces the four fields with one field holding `\int_a^b f(x)\,dx + \int_c^d g(y)\,dy`, the adapter must
split it into the same rows: the factor before each ∫ into `coef`, the subscript and superscript into `lower` and
`upper`, the body into `integrand` and the differential into `v`. A sum of integrals becomes one row per integral.

The result is one of:

- `{valid: false, message}`: the entry cannot be graded (an empty field, no dx/dy, an unreadable integrand, an
  integrand in the wrong variable). Nothing is graded, the student fixes the entry. `message` contains TeX inside
  `\( \)` and must be typeset.
- `{valid: true, ok: true}`: correct.
- `{valid: true, ok: false, note}`: wrong. `note` (TeX inside `\( \)`) is shown with the explanation.

### 2.2 How the setup is graded (v12.9.B)

v12.9.A graded an integral setup by its value only. v12.9.B checks the setup itself; the MathLive adapter must not
bypass this by sending a computed value.

- For each variable, the student's integrals are combined into one signed integrand (the coefficient times the
  integrand on each interval, with the sign of a reversed interval) and compared pointwise, at 67 sample points away
  from the endpoints, with the integrand of a model setup. The value must also match.
- Models are the setup in the explanation, any alternatives the problem lists (`answer.models`): the other method or
  the other variable where the problem allows it (the "either direction" area tasks, calculator solids where both
  washers and shells apply, the unnamed free-response volume setups), and, for a region symmetric about the middle of
  its interval, twice the integral over either half.
- Accepted as the same setup: an expanded or factored integrand, the constant inside or outside the integral, an
  interval split into pieces, reversed limits with the sign changed, calculator limits rounded to three or more
  decimal places.
- Refused, with a note when one applies: a setup that only has the right value (a constant, a rescaled integrand,
  other limits), the method or variable the question excludes (`answer.others`, with its own note), and common
  mistakes such as \((R-r)^2\), a missing \(\pi\), an unsquared radius or width, a shell without its radius.
- Not recognized (refused): a correct setup that is not one of the listed models, for example one rewritten by a
  substitution, or one that mixes dx and dy pieces for a region whose problem does not list that split. Prompts never
  claim that "any correct setup" is accepted; they say "either method" or "x or y" only where the alternative is a model.

### 2.3 Expressions (`u6-expr`)

`checkExpr(raw, answer)` takes one string in the linear syntax in the part's variable (`answer.variable`); it is graded
by value at sample points of `answer.domain`. It returns the same `{valid, ok, note | message}` shapes.

## 3. Behavior the pages rely on

- Enter in any field checks the part (the same as the Check button); the keypad's own Check key does the same.
- One keypad serves all fields of a part (`mountInputs(fields, panel, {mode, onCheck})`); in the integral control the
  empty fields are labeled `1` (number in front), `b`, `a` and `integrand` through CSS on `.bm-calc-empty`.
- `+ Add another integral` and `Remove last integral` show or hide rows; hidden rows are not graded.
- After grading, fields are disabled and the row is marked `.correct` or `.wrong`.

## 4. Tests a MathLive adapter must pass

- `node tools/review-lab/unit6/qa/integral-entry.mjs`: every model setup, typed in the linear syntax, is accepted
  (and with calculator limits rounded to four and three places); every listed alternative is accepted; every excluded
  setup and engineered same-value integrand is refused; common mistakes are refused.
- `node tools/review-lab/unit6/qa/checker-adversarial.mjs`: fifteen fixed cases (equivalent forms, alternatives,
  impostors with the right value, the symmetric half).
- `node tools/review-lab/unit6/entry.mjs <page> …` (browser): enters every part of generated problems through the
  physical keyboard and the on-screen keypad, alternating Enter and Check. It addresses the current DOM
  (`.bm-calc-editor`, `.bm-calc-source`, `.u6-int-row`, `.u6-dbtn`, `.u6-add`, `.staged-check`); if MathLive changes
  the DOM, this tool must be updated with it and must still pass on every Unit 6 page and Practice Type.
- `npm run qa:unit6`: every shown answer, typed, is graded correct.
