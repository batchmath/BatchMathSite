## Phase 1: strict rounding
Policy (`assets/unit5-answers.js`, helpers in `assets/unit5-core.js`):
- The authoritative answer is computed at full precision and rounded to the requested places (3, cents = 2, whole
  number = 0) **half away from zero** (1.2345 → 1.235, −1.2345 → −1.235, 2.5 → 3). A value within floating-point
  noise of a half step (10⁻⁹ of the last place plus a relative 10⁻¹²) counts as exactly half, so 1.005 at cents
  gives 1.01 even though its binary form is 1.00499….
- Generated problems never have an answer that close to a half step: `problem()` rejects any rounded answer within
  2·10⁻⁶ of a last place (plus a relative 10⁻¹⁰) of a half step and the engine draws new parameters. Grading never
  depends on integration or root-finding noise.
- The student's entry must be a decimal number equal to that rounded target, compared as integers of the last place
  (no tolerance): leading point (.923), sign, −0, trailing zeros (1.25 / 1.250 / 1.2500), `$`, thousands commas
  and a unit word are fine. A neighbouring value (1.234 for 1.235) and an unrounded value with extra non-zero digits
  (1.2503 for 1.250) are graded wrong, each with a note. An expression (ln(2)/5, 1/4, √2) is not graded: the
  student is asked for a decimal rounded as directed and can re-enter, so an unrounded calculator expression
  cannot stand in for the rounded number.
- Calculator interval endpoints and rounded lists follow the same rule endpoint by endpoint (exact whole-number
  endpoints such as 0 may stay whole); bracket conventions are unchanged. Exact answers (fractions, radicals, π,
  logarithms) and symbolic IVP checking are unchanged.
- Engines now state `places` instead of a tolerance (`basic`, `motion`, `growth`, `rate`). Motion's calculator
  direction intervals no longer pre-round endpoints to six places (that rounded twice: 1.2344996 → 1.234500 → 1.235).
- `fix()` and `money()` (answers shown and explanation values) use the same rounding.

## Phase 2: calculator / non-calculator infrastructure
- `makeEngine` (`assets/unit5-core.js`): every family states its kind — `calculator:true`, `calculator:false`, or
  `calc:{calculator:[tiers], noncalculator:[tiers]}` when it has both (only Rate's `one_rate` and `initial_change`
  in W). A request with `calc: 'calculator' | 'non-calculator'` filters families and tiers *before* choosing, asks
  the family for that kind (`make(tier, true|false)`), and throws if the result has the wrong kind (a bug, never a
  resample). An eligible-but-empty request (for example a calculator request for a non-calculator family, or a
  tier the kind does not have) throws an explanatory error instead of W's silent fallback to all families. An
  unknown or retired Practice Type (for example one a browser restores into the dropdown) is treated as mixed with a
  console warning, so it can never select a retired family. Mixed mode is unchanged (each family keeps its own mix).
- The page passes its mode in `BM_TOPIC_PRACTICE.calculator`; `register()` adds it to every generator call, so
  `assets/ap-topic-practice.js` is unchanged.
- New pages (copied from the topic's own page by `tools/build-unit5-pages.py`, with their own title, heading,
  breadcrumb, canonical URL, descriptions, structured data and analytics id `…_calculator` / `…_noncalculator`):
  `topics/basic-first-order-differential-equations/calculator-practice/`, `…/non-calculator-practice/`,
  `topics/motion-problems/calculator-practice/`, `…/non-calculator-practice/`. The existing `practice/` pages keep
  their URLs and Practice Types and are now titled "… Mixed Practice". Topic pages show three launch buttons
  (Mixed, Non-Calculator, Calculator with the Unit 3 calculator icon); sitemap entries added. SEO titles for Basic
  use "Basic First-Order DEs" to stay within 85 characters.
- Engine counts in `analytics-qa`, `release-qa`, `fraction-sign-equivalence-qa`, `seeded-browser-qa` and its
  browser-infra guard: 135 → 139.
- `qa/calc-eligibility.mjs` (part of `npm run qa:unit5`): 11 pages, 62 Practice Type options, 600 problems each:
  0 calculator leaks, 0 problems outside a fixed Practice Type, Mixed shares within tolerance of the renormalized
  weights; impossible requests raise errors; unknown types give mixed. Known gaps it reports (Phase 3): Motion has
  no foundational calculator problems; Rate has non-calculator problems only at the foundational tier.
- Browser: the four new pages, 6 problems each at 1366×768: every answer accepted, 0 scroll boxes, 0 overflow,
  0 console errors. `qa:static`, `qa:analytics`, `qa:display`, `qa:pwa`, browser-infra: pass; `qa:seo` the same 21
  pre-existing errors as W.
