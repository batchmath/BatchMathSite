CHANGES
-------
1. GitHub seeded-browser QA failures from v10.6.3.N
- Fixed Report a Problem initialization race: if a problem is generated before the report UI is
  inserted, the button is now created/revealed instead of remaining hidden.
- IM1 integer addition/subtraction problems now carry deterministic id/key values for reproducible reports.
- Unit 5 assignment comprehensive review no longer references retired slope-fields or exponential-growth
  generators. It now selects only the four live Unit 5 generators.
- Seeded-browser harness retains the previous snap:s repair, waits for the sitewide answer normalizer,
  checks its fraction-sign equivalence behavior, and uses one bounded same-seed retry for a CI load stall.

2. Sitewide negative-fraction equivalence
- Added /assets/answer-normalization.js and loaded it before problem tracking across all 89 current
  instrumented practice engines. Every current practice route also loads it.
- Equivalent negative fractions are canonicalized before answer checking. Examples accepted as the same:
    -1/2, (-1)/2, 1/-2, 1/(-2), -(1/2), and Unicode-minus variants.
- Symbolic fractions are handled as well, e.g. sqrt(2)/-2 and -(sqrt(2)/2).
- The normalizer deliberately does NOT pull a minus from only one term of a multi-term denominator,
  preventing the prior sign-cleanup regression class (e.g. 1/(-x+2) is left structurally intact).
- Defense-in-depth calls were also added directly to historically custom numeric/fraction parsers,
  all 16 normalizeInput expression-parser engines, IM1 fraction engines, shared AP topic practice,
  and Calculus Prep normalizers.
- Release QA now fails if a current/future practice route omits the sitewide normalizer.
- Basic Techniques for Indeterminate Limits generatorVersion bumped to 8.
